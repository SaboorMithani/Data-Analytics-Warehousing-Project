### 2\. Project Situation / Business Scenario:





Pharmaceutical businesses must effectively handle pharma sales, hospital consumption, and inventory information. Keeping consistent information along with tracking consumption in a pharmaceutical cold chain environment is critical for improved management and decision-making.



Yet, the data might originate through a variety of origins and forms, which renders it challenging to integrate, verify, and analyse reliably.



This project solves that issue by creating a data warehouse and business intelligence platform for pharmaceutical sales and demand information.





### 3\. Project Overview:



The project, Pharma Chain Data Warehouse and Business Intelligence, aims to provide a data engineering and analysis solutions.



It focuses on Sales and Demand Intelligence (SDI). It defines the data pipeline, warehouse structure, data quality checks, and analytical query layer required for analysing sales of medicines and healthcare need.





### 4\. Project Objectives:



The project, Pharma Chain Data Warehouse and Business Intelligence, aims to provide a data engineering and analysis solutions.



i) It focuses on Sales and Demand Intelligence (SDI). It defines the data pipeline, warehouse structure, data quality checks, and analytical query layer required for analysing sales of medicines and healthcare need.



ii) Gather and process sales of medicines and other data from sources.



iii) Authenticate input information and then do quality inspections.



iv) The data should be stored and organised in preparation for analysis.



v) Create fact and dimension tables for your data warehouse.



vi) Transform the original data into an analytical structure.



vii) Prepare analytical queries for sales and demand intelligence.



viii) Grafana dashboards provide visibility into workflow and system efficiency.





### 5\. Technologies Used:



i) Python: Data processing and pipeline development.



ii) Apache Airflow: Pipeline orchestration.



iii) PostgreSQL: Staging and relational data storage.



iv) DuckDB: Analytical data warehouse and query processing.



v) Docker: Containerized project environment.



vi) Grafana: Pipeline and system monitoring.



vii) SQL: Data transformation and analytical queries.





### 6\. System Architecture / Workflow:



The workflow follows the following process:



i) Source data is received in CSV format.



ii) Data is ingested into the pipeline.



iii) Data is staged in PostgreSQL.



iv) Data is transformed and organized for the warehouse.



v) Analytical data is stored and queried using DuckDB.



vi) Data quality checks help validate the processed data.



vii) Grafana dashboards monitor data engineering activities.



viii) Apache Airflow coordinates the pipeline workflow.





### 7\. Deliverables:



i) Data ingestion pipeline.



ii) Data warehouse model containing fact and dimension tables.



iii) Data transformation and validation processes.



iv) Data quality checks.



v) Analytical query layer.



vi) Grafana monitoring dashboards.



vii) Project documentation and verification results.
